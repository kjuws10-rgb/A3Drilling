# Manual Inspection 응답성·진행 표시 · 11.25.0

기준은 11.24.10 `26a7db3e27bb17c4b9f141f2831d168965d978d5`다. `feature/manual-inspection-performance-20261125.0`에서 작업하며 master에 병합하지 않는다.

## 바뀌는 사용 경험

- 현재 위치 측정과 진행 알림에서 전체 좌표·결과표·통계를 반복해서 만들지 않는다.
- 바뀌지 않은 점과 화면 자료는 재사용한다. 실제 측정값·필터·레벨이 바뀌면 즉시 새 값으로 갱신한다.
- 원문 보관과 최종 CSV 읽기·쓰기는 UI를 막지 않는 작업 스레드에서 처리한다. 엔진 상태 변경과 설비 동작 검증은 소유 스레드에 유지한다.
- 준비·자동 보관·정리 중에는 상단에 진행 막대와 짧은 상태를 보여준다. 오른쪽 메뉴를 접어도 표시된다. 측정 중 숫자는 실제 완료 응답 수를 사용하며, 소요 시간을 모르는 단계는 불확정 막대로 표시한다.
- STOP 요청 후 실제 정리·보관이 끝날 때까지 작업 중 상태를 유지한다.

화면 조작과 테마는 유지한다. 실측·대표 편차의 `현재 B + 편차`, 현재 Cell Init의 최종 Review 즉시 초기화, 원측정·NG·중복 방지·Undo·최종 CSV·Monitor/A1 연결은 바꾸지 않는다.

## 실제 비교한 범위

동결한 수정 전 소스와 수정 후 소스에 같은 합성 모델·동작·시험 코드를 사용했다. 예열을 제외하고 규모별 3회 측정했으며, 최종 비교는 다른 빌드/벤치를 멈추고 순서대로 실행했다.

32,000개 좌표에서 현재 위치 1점 측정의 중앙값:

| 항목 | 수정 전 | 수정 후 |
| --- | ---: | ---: |
| UI 입력 처리의 최장 간격 | 1,071.7 ms | 20.7 ms |
| 명령 전체 완료 시간 | 1,071.7 ms | 409.6 ms |

이 시험은 실제 Core/Controller와 전체 원문 JSON의 임시 파일 보관을 포함한다. 실제 View 렌더링, Native Recipe/Review CSV I/O, Vision 통신·이동·레이저 시간은 제외한다. UI 입력 간격은 10 ms heartbeat로 관찰한 지표이며 화면 FPS나 모든 상황의 최대 지연 보장이 아니다.

중간 자동 보관이 꼭 필요한 상태를 별도로 유도한 진단에서도 입력 간격 중앙값이 1,237.0→26.9 ms로 줄었다. 이 진단은 timestamp만 조정하며 임의 sleep은 넣지 않았고, 정상 처리 속도 표와 구분한다.

실제 WPF View도 같은 8,000개 합성 좌표로 별도 비교했다. 상태 알림 24회와 선택 변경 12회를 같은 순서로 실행했다.

| View 작업 | 수정 전 중앙값 | 수정 후 중앙값 |
| --- | ---: | ---: |
| 최초 작업 중 표시 전환 | 64.3 ms | 18.2 ms |
| 상태만 바뀌는 알림 | 70.3 ms | 1.7 ms |
| 선택 변경 | 67.5 ms | 50.7 ms |

이 값은 렌더 요청과 Dispatcher 처리까지의 국소 관찰값이다. 화면 FPS·실장비 응답 시간은 아니다. 선택 동작이 느려지는 렌더 캐시 실험은 제외하고 기존 그리기를 유지했다. 변경 없는 자료의 재구성과 불필요한 화면 갱신만 줄였다.

## 데이터 보관·검증

전체 복구 자료는 유지한다. 저장 JSON의 불필요한 공백만 줄이고, 소유 스레드에서 불변 스냅샷을 캡처한 뒤 직렬화·원자 저장을 기다린다. 주기 보관도 응답/공식 결과 한 행이 완료된 경계에서 기다려 다음 이동 전에 완료한다. 저장 실패 시 다음 행을 실행하지 않으며 기존 원측정과 잔여 상태를 보존한다.

원본 CSV SHA 확인과 좌표/Recipe/기판 회차/실제·SIM 검증은 생략하지 않는다. 단순 파일 시간·길이 캐시로 현재성을 추측하지 않는다. 동기 완료 가능한 파일 저장소도 작업 스레드에서 실행하고, 기다린 뒤 선택·기준을 다시 검사한다.

실제 설비 App·CManager 초기화, PLC/Vision/모션/벤더 API·AeroScript 업로드/실행·레이저는 실행하지 않는다. 첫 대형 모델 구성·파일 보관 등 필요한 시간은 남을 수 있으며 진행 표시로 구분한다. 다른 PC와 실제 설비에서는 통신 시간·DPI·그래픽 환경을 포함한 확인이 필요하다.

이번 성능 수치는 현재 위치 한 점 측정과 화면 알림·선택을 대상으로 한다. 긴 Flying 전체 배치의 처리량까지 개선됐다는 의미는 아니다. 첫 32,000점 모델을 화면 자료로 구성할 때는 약 160 ms의 초기 지연도 남아 별도 현장 확인 대상으로 둔다.

최종 Release 빌드는 경고 0·오류 0이다. Core 294, 실제 DLL Controller 296, Backend/CSV 189, 가정한 보정 폐루프 21, 이전 직렬화 호환 37, 변경 범위 36, WPF 20개 모드 1,075개 검사를 통과했다. 소스 연결 Controller 293개는 실제 DLL 검사와 중복 합산하지 않는다. 파일 읽기 오류·취소·동일 경로 SHA 변경과 자동 보관 실패·STOP 중 정리도 검사했다.
