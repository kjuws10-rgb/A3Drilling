## 기존 저장 형식과의 연결

화면 위치는 Beam별이지만 기존 Review Offset CSV의 활성 저장 키는 Cell/Shot이다. 같은 Cell/Shot의 다른 Beam이 서로 다른 최종 보정값을 요청하면 저장을 거부한다. 한 Beam을 적용하면 같은 저장 키를 공유하는 다른 Beam의 표시 B도 같은 값으로 갱신한다. 실제 저장은 기존 축 변환을 거쳐 design mm를 사용하며 UI의 μm를 그대로 CSV에 쓰지 않는다.

첨부의 HTML 시뮬레이션을 실행한 독립 oracle와 새 C# 계산/상태/파일·WPF 테스트는 서로 다른 검증이다. HTML oracle 통과를 장비 정식 빌드·실제 모션/Vision 합격으로 보고하지 않는다. 장비 프로그램·컨트롤러·벤더 DLL은 이 시험에서 실행하지 않는다.

## 대표값 적용 이력

대표점의 동일 원측정을 이미 보정에 사용했다면 다시 `B + 원측정`을 더하지 않고 현재 활성 `B`를 대표 최종값으로 사용한다. 같은 Cell/Shot을 공유하는 다른 Beam의 보정으로 `B`가 변경된 경우도 같다. 다른 Shot에 대표값만 복사해 대표점의 `B`가 바뀌지 않은 경우에는 여러 대상 그룹에 같은 최종값을 계속 복사할 수 있다. 새 실측이면 새 raw로 계산하되, 과거 raw A → 새 raw B → 과거 A 순서로 다시 나타나도 과거 A는 재누적하지 않는다. 소비 이력은 전체 raw와 같은 Run의 과거 Beam 표시 키까지 보존하며, 새 위치나 장비 동작을 만드는 용도로 사용하지 않는다.

파일 저장에 전달하는 불변 스냅샷은 driving 후보뿐 아니라 저장 키를 공유하는 native 형제 Beam의 소비 토큰도 포함한다. 스냅샷 변조·저장 실패·취소에서 활성값/소비 이력을 바꾸지 않고, 이미 소비한 companion 토큰이 새 driving 실측의 정상 적용을 막지는 않는다. 재시작 시에는 실제 적용 이력으로 확정된 토큰만 복구한다.
