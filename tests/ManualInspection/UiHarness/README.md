# Native Manual Inspection UI harness

For version 11.21.1, append `--offset-init`. The 37 additional checks cover the single all-Cell button, screen-only whole-model initialization, protected-offset descriptions, confirmation/cancel/save dispatch, portable-file menu, pending-edit boundaries and no user read-only mode. They also verify the new OFFSETS/HEAD/all-heads default, cumulative B taking precedence over residual/raw values, explicit zero versus missing rows, multi-Cell/Head/Auto/fixed/fit populations and separation from camera originals. See [OFFSET_INIT_QA.md](../OFFSET_INIT_QA.md). Earlier working-measurement suites now select WORKING/CELL explicitly, and their readonly expectations are updated for current-plan reconnection; no old case is removed.

Run from the repository root on Windows with the .NET 8 Windows Desktop runtime and a suitable SDK:

```powershell
dotnet run --project tests/ManualInspection/UiHarness/ManualInspection.UiHarness.csproj -c Release -- Drilling.UI D:/A3Qa/ManualInspectionUi
```

The first argument points to the actual `Drilling.UI` folder so the harness reads the current Light/Dark dictionaries and the existing shared button/panel/grid styles. The output must be a separate local QA folder. The harness directly links the five production UI source files. Its fake controller captures requests; it does not load or start the equipment application, vendor SDK, motion controller, Vision communication or AeroScript.

An off-screen STA WPF window provides real layout/presentation and produces PNG previews plus `ui-results.json`. Checks cover both themes, table paging, the current-cell/Head/selected-cells scatter scopes, original versus proxy values, selection/rectangle selection, bounded cursor-centred zoom, visual-only pan, busy/read-only context commands, current-version controller requests and a 10,000-point full-dataset fit. The render time is a local observation, not an equipment tact or production performance guarantee.

Manual visual checks must also inspect the PNGs for clipped labels, numeric units, mixed OK/NG/proxy states and the correction/scatter/results panels. These tests complement the Common/session and production bridge/writer tests; they do not certify physical axis directions or machine safety.

For the subsequent integration changes, append `--integration-impact`. This runs a separate targeted report (`ui-integration-impact-results.json`) covering the IMPORTED filter/provenance, engine-resolved reference final F, same-Beam Flying row expansion, controller-backed full history and level-name constraints.

For the simplified UI and shared applied-offset Level policy, append `--sync-levels`. It creates `ui-sync-levels-results.json` and simplified Light/Dark PNGs. It checks the actual native description/confirm/cancel dispatch through an internal test seam, default active-B colors across Cell/Head/Rough/Fine/manual origins, applied zero versus missing offset, separation from candidate F and measurement results, common inclusive Level thresholds, external source/path details, recent-result selection without a file picker, and version changes while a confirmation is open. The main 49-check suite and 23-check integration suite were updated for the intentionally removed SIM/duplicate controls and are still separate from the new checks. No test starts the equipment Root, Manager, SDK, controller or Vision service.

For measurement-derived correction coverage and the compact workspace, append `--coverage-compact`. The 71 checks verify measured-history classification and Level/scatter/filter/table consistency without fabricating raw data, explicit zero versus missing offsets, native measurement precedence, recent errors and invalid/masked/candidate boundaries. They also check both themes at 1480×900, 1120×720 and 1120×560: no default left/right scrolling, collapsed results/scatter/details, a map that fits inside its parent and retains every visible slot, and the five point-context actions after removal of the right-side buttons. PNGs use the `coverage-<theme>-<size>.png` names. The 560-pixel height simulates the smaller view left below the existing Correction chrome. Expanded tables, scatter, settings or error messages can intentionally need local scrolling.

For the external-Review/UI interaction hardening, append `--hardening`. The 30 checks produce `ui-hardening-results.json` and `hardening-dark.png`. They verify that selecting an independently scoped scatter point reveals it through same-Cell Head/judge/source/search filters, while keeping already-useful filters and Ctrl selections; external source changes invalidate an ineligible representative; read-only recovery removes its previous notice; and local validation messages survive layout/selection refresh until the next source snapshot. Confirmation cancellation and an external Review update during an Apply confirmation must dispatch no request. The common UI request gate blocks stale or read-only control/write/settings requests, permits read-only source reload/file viewing/export, preserves the busy rule for details, and always delivers STOP. This is a presentation/dispatch check with a fake controller; the production controller's independent lineage/version/interlock validation remains required. The initial unmodified production UI failed 13 of these 30 checks; retain that private baseline report separately when reproducing the regression.

For the visual-polish and usability regression, append `--visual-usability`. Its 105 checks produce `ui-visual-usability-results.json`, Light/Dark compact/wide/DPI previews, 32,000-point matrix fit, two review/scatter preview scenes and flat context-menu PNGs. Checks cover exact transformed map hit coordinates, hidden selections and operation scope, cancelled/capture-lost/unloaded/stale/filter-changed gestures, invalid zoom input, real inner TextBox event sources, read-only accessibility peers/names, icon names, progress-only cache reuse versus fresh-measurement invalidation, Head 0/invalid Head option boundaries, coincident scatter cycling and partial/full Ctrl group selection, equal X/Y scale, primary-text contrast, and local flat-menu themes. The previous 207 checks remain separate and retain their original counts; the applied-B text check now verifies the shorter B value, distinct correction Level and full tooltip explanation.

DPI125/150 here means equivalent DIP space for a 1400×900-pixel screen plus higher-resolution bitmap rendering; this harness does not change Windows monitor DPI. Directional Up/Down focus traversal is recorded separately as inconclusive when both the flat and ordinary system ContextMenu refuse keyboard focus in the same off-screen nonactivated window. Those two cases are excluded from the 105 pass count. Routed Enter activation, cancellation with no host request, Escape dismissal and style/disabled state are tested. The harness never activates the user's desktop window or injects highlight state to pass a check. Real monitor DPI and native keyboard-focus traversal remain field UI checks.

For the map-first layout, append `--map-first`. The additional 73 checks produce `ui-map-first-results.json`, compact/wide/125%/150% Light/Dark images, an expanded inspection/correction image, expanded work information/legend, four filled Level tiles and a 32,000-point fit image. At a requested 1120×560 window, the map must be at least 1000×360 DIPs, with no default scrolling or parent clipping. The inspector, results, scatter and work information stay folded initially and remain available on demand. Dense group grids must use the group width, and actual bitmap pixels must show the correct Level color over at least 90% of each of four test slots.

Double-click checks call the same helper/first-click tracking methods as the real left-down/up handlers. They verify fit at zoom 1/pan 0, gesture/capture cleanup, no device/correction request, pre-click multiple/empty selection and explicit null-focus restoration, and invalidation after snapshot/drag changes. This is a deterministic handler-path test, not physical OS mouse input injection. The preceding 312 checks are retained: closed inspector/legend layout uses actual visibility and BorderThickness; history actions explicitly select their point instead of relying on the removed implicit first-point target; synchronization details are verified in the retained tooltip plus the short visible waiting status; and the shorter selection-menu caption is found through its operation tooltip.

For Recipe cell overview, scatter axes and temporary-file workspace return, append `--cell-overview`. Its 72 checks produce `ui-cell-overview-results.json` with current hashes of the five linked production UI files, plus Light/Dark compact/wide/125%/150% images. The fixture deliberately gives Cell numbers a different order from their physical polygon positions. It checks whole-Cell Ctrl selection, single-Cell/header navigation, rotated polygon hit testing, Y orientation, a geometry-only empty Cell and fixed geometry under point filters. Small-error Auto ranges do not inherit the tolerance or a 5 µm floor; fixed axes clip only display hits, zoom preserves the cursor's value, and fit/double-click restores the complete selected-Cell population and pre-click selection/focus. External source or scope changes invalidate old click restoration; changing a range clears stale hits before the next render. Five compact/wide layout checks preserve an expanded map minimum of 240 DIPs or 45% of the workspace viewport, allow scrolling to the complete scatter plot, and restore the original no-scroll map-first layout when folded.

The same new mode checks selected-Cell auto-follow versus manual checkbox priority, explicit file-menu actions without session/recent-result UI, return confirmation/cancellation and restoration of original selection, filters, map/scatter zoom, axes and inner/outer panel states. Incomplete measurements cannot be erased by opening another file or returning through the common UI dispatch gate. These are source-linked WPF/fake-controller checks; physical mouse timing and real device execution remain separate field checks. The preceding 385 checks are retained. The three former recent-result/menu checks now verify the deliberately simplified return/file/CSV menu and its equivalent description/dispatch safety; the original map icon checks use their accessibility names because scatter now has its own `+`/`−` buttons.
