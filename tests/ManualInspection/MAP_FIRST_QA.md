# Manual Inspection · 2D 지도 중심 개편

기준은 `7c6cd31ecaa5b201e6138c59fa757f2f87e292d8`, 브랜치는 `feature/manual-inspection-map-first-20261120`이다. 기존 테마와 보정 기능을 유지하고 기본 화면을 지도 중심으로 바꾼다. master에는 병합하지 않는다.

- **큰 사각 타일**: 작은 점 대신 각 슬롯을 채우는 Level 색상 사각형을 사용한다. Cell/Head 구획 안의 행렬도 가로·세로 공간을 모두 사용한다. 필터로 숨긴 점을 다른 슬롯으로 재배치하지 않는다. 타일 글자는 배경색에 맞춰 검정/흰색 중 대비가 높은 쪽을 사용한다.
- **지도 우선**: 상단에는 자주 쓰는 조작·상태·선택수·STOP만 둔다. 우측 `검사 · 보정`은 기본 접힘이며 열 때만 300px을 사용한다. 측정 결과 표·산포도·필터/범례/작업 정보는 하단 접이식으로 연다.
- **더블클릭 맞춤**: 지도에서 좌측 버튼으로 더블클릭하면 배율 100%·화면 맞춤과 pan=0으로 복귀한다. 첫 클릭에서 잠시 바뀐 선택도 같은 기준이면 원래 복수 선택·초점으로 복원한다. 데이터/필터/회차가 바뀌거나 드래그한 경우에는 과거 선택을 새 기준에 복원하지 않는다.
- **동작 구분**: 맞춤·확대·보기 이동은 장비를 움직이거나 측정·보정 저장을 실행하지 않는다. Ctrl 클릭/드래그 선택·Ctrl 휠·Alt 이동·우클릭 동작·확인·STOP 정책은 유지한다.

지도는 **행·열 논리 배치**이며 실제 기판 mm 축척의 도면은 아니다. 여기서 ‘셀 영역 채움’은 화면의 논리 슬롯 경계까지 색상을 채우는 표시다. 활성 B와 측정 편차의 공통 Level·출처 구분도 그대로다.

## 검증

실제 WPF 합성 데이터에서 기본 1120×560의 지도 약 **1069×386px**, 기본 가로·세로 스크롤 0을 확인했다. 양테마·넓은 화면·125/150% 등가 DIP 공간·32,000점 Fit, 펼친 검사/보정·표·산포도·작업 정보 접근과 다시 접었을 때의 복귀를 검사한다.

L1~L4 타일의 내부 픽셀을 샘플링해 **97.14~97.88%**가 해당 Level색과 일치하는 것을 확인했다. 글자·테두리 픽셀을 포함한 검사이며 최소 기준은 90%다.

더블클릭 검사는 실제 mouse-down handler가 호출하는 helper를 사용한다. 두 클릭의 분리 단계도 재현하여 복수 선택·빈 선택/null 초점 복원, 기준 변경 시 옛 선택 복원 거부, 드래그 결과 보존, 캡처/gesture 정리, Busy/조회 전용에서도 화면 맞춤만 수행함을 확인한다. 물리 마우스 입력 주입 시험과 구분한다.

```powershell
dotnet run --project tests/ManualInspection/UiHarness/ManualInspection.UiHarness.csproj -c Release -- Drilling.UI D:/A3Qa/MapFirst --map-first
```

기존 UI 회귀에서 기존 고정 우측 패널·상단 여러 줄·이전 버튼 문구에 의존한 setup은 새 접기 위치에 맞게 수정한다. 데이터/Level·입력·대상 확인 검사는 유지한다. 실제 Border의 두께·padding으로 부모 경계를 확인하며 옛 2px 고정값으로 새 Border를 잘못 탈락시키지 않는다. 최종 검사 수·소스/DLL/그림 SHA는 [validation.json](../../docs/ManualInspection/validation.json)을 따른다.

실제 장비 App/Root/Manager·벤더 SDK·모션/PLC/Vision·AeroScript·레이저는 실행하지 않는다. 실제 모니터 DPI 전환·활성 창 메뉴 Up/Down 포커스·설비 동작/정밀도 확인은 앞선 [검증 한계](VISUAL_USABILITY_QA.md)를 유지한다.
